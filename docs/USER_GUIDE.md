# Руководство пользователя

## Идея приложения

ProdNote помогает вести работу как связанный журнал:

- задача отвечает на вопрос "что нужно сделать";
- заметка хранит конспект или отдельный материал;
- таймер и помодоро фиксируют фактическое время;
- календарь показывает план и историю;
- статистика показывает, куда ушло время.

Все данные остаются в браузере. Для бэкапа используйте экспорт `.prodnote.json`.

## Обзор

Экран "Обзор" показывает:

- сколько времени записано сегодня;
- сколько активных задач есть сейчас;
- общее время по всем сессиям;
- текущий поток задач;
- последние рабочие сессии;
- распределение времени по проектам;
- свежие заметки;
- ритм последних рабочих дней.

Этот экран удобен как стартовая точка дня.

## Задачи

В задачах есть два режима:

- "Канбан": компактный обзор по статусам.
- "Список": подробный режим для просмотра и ведения журнала.

Статусы задач:

- "Бэклог": задача зафиксирована, но работа не началась.
- "В работе": задача активна.
- "Заблокировано": есть внешний блокер или не хватает контекста.
- "Готово": задача завершена.

У задачи можно указать:

- название;
- описание;
- проект;
- приоритет;
- дедлайн;
- теги.

Журнал задачи ведется в режиме "Список". В журнал стоит писать:

- что было сделано;
- какие решения приняты;
- какие ссылки или материалы изучались;
- что нужно проверить дальше;
- краткий конспект работы.

## Заметки

Заметки отделены от задач, но могут быть связаны с ними.

Заметка подходит для:

- конспектов;
- исследовательских материалов;
- черновиков;
- решений, которые не являются задачей;
- справочной информации.

Формат заметок - Markdown. Поддерживаются базовые конструкции:

```md
# Заголовок
- пункт списка
- **важное**
> цитата или вывод
```

HTML внутри Markdown экранируется, чтобы preview был безопаснее.

После сохранения заметка появляется в базе знаний. Кнопка "Открыть" сначала показывает заметку в полноэкранном отрендеренном виде. В этом режиме можно нажать "Редактировать", изменить Markdown и сохранить.

При каждом сохранении изменений приложение добавляет в историю дату и время редактирования.

## Календарь

Календарь содержит две линии:

- план: будущие фокус-сессии, дедлайны и ревью;
- факт: завершенные таймерные, ручные и помодоро-сессии.

Планирование удобно использовать так:

- выбрать задачу;
- создать фокусный слот;
- позже запустить таймер или помодоро по этой задаче;
- после работы увидеть фактическое время в истории.

Ручная сессия нужна, если вы уже поработали, но забыли включить таймер.

## Фокус

Экран "Фокус" используется для активной работы.

Можно запустить:

- обычный таймер;
- помодоро.

Обычный таймер идет до ручной остановки. После остановки создается `TimeSession`.

Помодоро использует настройки:

- фокус: 25 минут;
- короткий перерыв: 5 минут;
- длинный перерыв: 15 минут;
- длинный перерыв после 4 фокус-сессий.

Эти значения можно изменить в настройках.

Фокусная фаза помодоро записывает рабочую сессию. Перерыв не записывается как рабочее время.

## Статистика

Статистика показывает:

- общее записанное время;
- количество помодоро-сессий;
- лучший рабочий час;
- heatmap последних 28 дней;
- время по проектам;
- время по задачам;
- время по тегам;
- распределение по часам суток.

Важно: статистика строится только по завершенным сессиям. Активный таймер появится в статистике после остановки.

## Настройки

В настройках можно:

- изменить длительность помодоро;
- выбрать первый день недели;
- экспортировать данные;
- импортировать данные;
- создать проект;
- удалить проект;
- создать тег.

Удаление проекта не удаляет задачи и заметки. Связанные задачи и заметки переходят в состояние "Без проекта".

## Бэкап и перенос данных

Экспорт создает файл:

```text
prodnote-YYYY-MM-DD.prodnote.json
```

Файл содержит:

- проекты;
- задачи;
- заметки;
- теги;
- сессии времени;
- помодоро-циклы;
- планы календаря;
- настройки.

Импорт заменяет текущие локальные данные. Перед импортом приложение показывает подтверждение с количеством сущностей.

Рекомендуемый рабочий процесс:

- экспортировать файл после важных изменений;
- хранить копию вне браузера;
- перед экспериментами делать экспорт;
- импортировать только доверенные файлы.
